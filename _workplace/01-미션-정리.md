## 1. 한 문장 정의

> **n×n 패턴이 Cross 필터와 X 필터 중 어느 쪽에 더 가까운지를, MAC 연산으로 직접 계산해 판정하는 Python 콘솔 프로그램을 만든다.**

## 3. 개발 환경 · 제약

| 항목 | 규정 |
| --- | --- |
| 언어 | Python **3.8 이상** |
| 허용 라이브러리 | 표준 라이브러리만 (`json`, `time`, `sys` 등) |
| **금지** | NumPy, pandas 등 **모든 외부 라이브러리** |
| **금지** | 벡터화 연산 — MAC은 **반드시 반복문으로 직접 구현** |
| 안정성 | 모드 2에서 스키마/크기 오류가 나도 **프로그램이 중단되면 안 됨** (케이스 단위 FAIL 처리) |

> ⚠️ `sum()`/`zip()` 같은 내장 함수는 표준 라이브러리이므로 허용 범위이지만, "반복문으로 직접 구현" 취지에 맞게 **이중 for 루프 구현을 기본형으로 제출**하고, 최적화 버전은 보너스 항목에서 별도 비교하는 것을 권장한다.

## 4. 기능 요구사항 체크리스트

구현하면서 그대로 체크할 수 있도록 원본 4장·7장을 통합해 정리했다.

### F1. 데이터 구조
- [ ] n×n 2차원 패턴/필터 저장
- [ ] 특정 위치 값 읽기/쓰기
- [ ] 최소 **3×3, 5×5, 13×13, 25×25** 처리

### F2. 모드 1 — 사용자 입력 (3×3)
- [ ] 필터 A를 3줄, 공백 구분으로 입력받아 저장
- [ ] 필터 B를 동일 방식으로 입력
- [ ] 패턴을 동일 방식으로 입력
- [ ] **입력 검증**: 행 수 / 열 수 불일치, 숫자 파싱 실패 감지
- [ ] 오류 시 안내 문구 출력 후 **재입력 유도** (종료 금지)
  - 예: `입력 형식 오류: 각 줄에 3개의 숫자를 공백으로 구분해 입력하세요.`
- [ ] A 점수 / B 점수 / 연산 시간(ms) / 판정(A·B·판정 불가) 출력

### F3. 모드 2 — `data.json` 로드 및 스키마 검증
- [ ] `filters`에서 `size_5`, `size_13`, `size_25` 로드
- [ ] `patterns`에서 `size_{N}_{idx}` 키, `input`(2차원 배열), `expected` 로드
- [ ] 패턴 키에서 **N을 추출**해 대응하는 `size_N` 필터 선택
- [ ] 필터와 패턴의 **크기 일치 검증**
- [ ] 불일치 시 → 해당 케이스만 **FAIL 처리 + 원인 메시지**, 프로그램은 계속 진행

### F4. 라벨 정규화 (필수)
- [ ] 내부 표준 라벨은 **`Cross`, `X`** 2가지만 사용
- [ ] `expected` 값 정규화: `'+'` → `Cross`, `'x'` → `X`
- [ ] filter 키 정규화: `'cross'` → `Cross`, `'x'` → `X`
- [ ] 콘솔 출력과 PASS/FAIL 비교는 **모두 표준 라벨 기준**

### F5. MAC 연산
- [ ] 위치별 곱 → 전체 합
- [ ] 외부 라이브러리 없이 반복문 직접 구현
- [ ] 결과는 `float` 반환 가능

### F6. 점수 비교 정책
- [ ] **epsilon 기반** 비교 적용
- [ ] 권장 기준: `abs(score_a - score_b) < 1e-9` → **동점(UNDECIDED)**
- [ ] 동점이 아니면 큰 쪽으로 판정
- [ ] 판정 == expected → `PASS`, 아니면 `FAIL`

### F7. 성능 분석
- [ ] 크기별 MAC 연산 시간을 **ms 단위**로 측정
- [ ] 각 크기별 **최소 10회 반복 후 평균**
- [ ] I/O(입력·출력·파일 읽기) 제외, **연산 함수 호출 구간**만 측정 (권장)
- [ ] 표 컬럼: **크기(N×N) / 평균 시간(ms) / 연산 횟수(N²)**

### F8. 결과 리포트
- [ ] 콘솔: **전체 테스트 수 / 통과 수 / 실패 수**
- [ ] 콘솔: 실패 케이스의 **식별자 + 실패 사유 요약**
- [ ] README: 실패 원인 분석 + 시간 복잡도 분석 **10줄 이상**

## 5. 판정 규칙 요약표

| 조건 | 판정 | PASS/FAIL |
| --- | --- | --- |
| `abs(A - B) < 1e-9` | `UNDECIDED` (판정 불가) | 항상 **FAIL** (expected와 결코 일치할 수 없음) |
| `A > B` | `Cross` (모드 1에서는 `A`) | expected == Cross 면 PASS |
| `B > A` | `X` (모드 1에서는 `B`) | expected == X 면 PASS |
| 필터/패턴 크기 불일치 | — | **FAIL** + 원인 메시지, 프로그램 계속 |
| 해당 size 필터 없음 | — | **FAIL** + 원인 메시지, 프로그램 계속 |

## 6. 실행 흐름 (원본 4-4장)

```text
프로그램 시작
  └─ [모드 선택] 1) 사용자 입력(3×3)   2) data.json 분석

  ── 모드 1 ────────────────────────────────────────
     필터 A 입력 → 필터 B 입력 → (저장 확인)
     → 패턴 입력 → MAC 연산 → 결과 판정
     → 성능 분석(3×3) 출력

  ── 모드 2 ────────────────────────────────────────
     필터 로드 → 패턴 로드/검증
     → 케이스별 MAC 연산 / 판정 / PASS·FAIL 출력
     → 성능 분석(3×3 포함, 5×5 / 13×13 / 25×25) 출력
     → 결과 요약(총/통과/실패 + 실패 목록) 출력
```

> 📌 **주의**: 성능 분석표에는 **3×3이 포함**되어야 하는데 `data.json`에는 `size_3` 필터가 **없다**.
> → 3×3용 필터/패턴은 프로그램 내부에서 **자체 생성**해야 한다 (보너스의 "패턴 생성기"를 여기에 재활용하면 깔끔하다).

## 7. 보너스 과제 (선택)

### B1. 시뮬레이터 최적화 — 메모리 접근
- 2차원 배열을 길이 `N²`의 **1차원 배열로 평탄화(flatten)** 해 접근 패턴 단순화
- **동일 입력 / 동일 반복 횟수**로 최적화 전·후 성능 비교

> 실측 결과(→ [02-개념-도식.md](02-개념-도식.md) §6)에 따르면 순수 CPython에서는 1D 평탄화가
> **작은 N에서만 유리**하고 큰 N에서는 이득이 사라진다. "무조건 빨라진다"고 쓰지 말고 **측정값 그대로 서술**할 것.

### B2. 패턴 생성기
- 크기 `N`을 입력하면 `N×N` Cross / X 패턴 자동 생성
- 생성 결과를 **모드 1 및 성능 분석에 재활용** 가능하게 구성

```text
Cross(N): 중앙 행 전체 = 1, 중앙 열 전체 = 1   (N이 홀수일 때 중앙 = N//2)
X(N)    : 주대각선 (i == j) = 1, 반대각선 (i + j == N-1) = 1
```

## 9. 학습 목표 — "설명할 수 있어야 하는 것"

원본 3장. README와 발표에서 아래 6가지에 답할 수 있어야 한다.

1. **MAC이 무엇이고 AI에서 왜 중요한가** → 곱셈+누적합, CNN 합성곱의 최소 단위, NPU가 병렬화하는 대상
2. **곱하고 더해서 유사도가 나오는 원리** → 같은 위치가 동시에 켜져 있을 때만 점수가 쌓임 (내적 = 방향 일치도)
3. **라벨 정규화가 왜 필요한가** → `'+' / 'x' / 'cross'` 등 표기가 소스마다 다름. 비교 직전에 표준형으로 모으지 않으면 비교 자체가 무의미
4. **부동소수점 오차와 epsilon** → `0.1`은 이진수로 정확히 표현 불가. 누적합 순서만 달라도 최하위 비트가 흔들림 → `==` 비교 금지
5. **O(N²) 근거** → 필터 한 장당 MAC 횟수는 정확히 `N²`. N이 2배면 시간은 약 4배
6. **실패 원인 3분류** → ① 데이터/스키마 문제 ② 로직 문제 ③ 수치 비교 문제 (→ 이번 `data.json`의 FAIL은 **①에 가까운 데이터 설계 문제**, [03](03-data.json-분석.md) 참고)
